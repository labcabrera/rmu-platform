= RMU Platform AWS Infrastructure
:icons: font
:toc: left
:toclevels: 3

This Terraform project defines the AWS infrastructure required to run RMU Platform.

The target architecture is:

* A single S3 bucket as the private static asset repository for all micro-frontends.
* One CloudFront distribution per MFE, each attached to its own domain alias.
* A single EC2 instance running the API Docker Compose stack.
* An Application Load Balancer routing API traffic by host header to the EC2 instance ports.
* Route53 records created from the main hosted zone, by default `labcabrera.com`.
* ACM certificates for CloudFront in `us-east-1` and for the ALB in the selected AWS region.

== Structure

[options="header"]
|===
|Path |Purpose

|`versions.tf`
|Terraform and provider version constraints.

|`providers.tf`
|AWS provider configuration, including the `us-east-1` alias required by CloudFront certificates.

|`variables.tf`
|Platform-level input variables.

|`locals.tf`
|Derived names, tags, and domain lists.

|`main.tf`
|Composition root for DNS, certificates, network, static MFEs, and API runtime.

|`outputs.tf`
|Useful deployment outputs.

|`terraform.tfvars.example`
|Example configuration without secrets.

|`user_data.sh.tftpl`
|EC2 bootstrap script that installs Docker and starts the API Docker Compose stack.

|`modules/network`
|VPC, public subnets, internet gateway, and routing.

|`modules/static_mfe`
|S3, CloudFront distributions, OAC, bucket policy, and DNS records for MFEs.

|`modules/api_host`
|EC2 instance, ALB, target groups, listener rules, security groups, and DNS records for APIs.
|===

== Usage

[source,bash]
----
cd terraform
cp terraform.tfvars.example terraform.tfvars
----

Edit `terraform.tfvars` and provide project-specific values. Keep secrets out of version control.

[source,bash]
----
terraform init
terraform plan
terraform apply
----

== Static MFE Deployment Model

All micro-frontends are stored in the same private S3 bucket. Each CloudFront distribution points to a different `origin_path`, for example `/shell`, `/core`, or `/tactical`.

This keeps frontend storage centralized while allowing independent cache policies, domains, and invalidations per MFE.

== API Deployment Model

The API services run in Docker on a single EC2 instance. Terraform writes the configured Docker Compose content and environment variables to `/opt/rmu-platform` during instance bootstrap, then runs:

[source,bash]
----
docker compose --env-file .env -f docker-compose.yaml up -d
----

The ALB routes traffic to the instance by subdomain. For example, `core-api.labcabrera.com` can route to port `3001`, while `items-api.labcabrera.com` can route to port `3006`.

== Secrets

Use the sensitive `api_environment` variable for Docker Compose values that must not be committed. The example file intentionally uses placeholders.

Consider migrating production secrets to AWS Secrets Manager or SSM Parameter Store before using this stack for a real environment.
