= Services catalog
:toc: left

Every service lives in its own repository and publishes its own image. `rmu-platform` consumes the images in `compose/apis.yaml`, with versions pinned through `RMU_API_<NAME>_VERSION` in `.env`.

All APIs except Attack Tables and NPC Names depend on MongoDB, and the NestJS ones also on Kafka. The NestJS APIs share the platform and conventions of the `rmu-api-core` template (Node 24, pnpm, native ESM, Vitest, the HTTP error contract and optimistic concurrency; workspace specs 014, 015, 018 and 020), and compose runs them with `init: true` so `SIGTERM` reaches Node.

=== Environment convention

APIs are configured through `RMU_*` variables. In `compose/apis.yaml` they are built from the shared values in `.env`:

[options="header",cols="2,3"]
|===
|Variable |Value

|`RMU_MONGO_<DOMAIN>_URI`
|`mongodb://${MONGO_USER}:${MONGO_PASSWORD}@rmu-mongo:27017/rmu-<domain>?authSource=admin`

|`RMU_IAM_ISSUER_URI`, `RMU_IAM_AUDIENCE`
|`${RMU_IAM_ISSUER_URI}`, `${RMU_IAM_AUDIENCE}` from `.env` (public issuer and `rmu-api`)

|`RMU_IAM_JWK_URI`, `RMU_IAM_TOKEN_URI`
|`${RMU_IAM_BASE_URI}/realms/${RMU_IAM_REALM}/protocol/openid-connect/{certs,token}`

|`RMU_IAM_CLIENT_ID`, `RMU_IAM_CLIENT_SECRET`
|The confidential `rmu-client` (`RMU_IAM_CLIENT_ID`, `RMU_IAM_CLIENT_SECRET` in `.env`).

|`RMU_KAFKA_BROKERS`, `RMU_KAFKA_CLIENT_ID`, `RMU_KAFKA_CONSUMER_GROUP_ID`
|`${RMU_KAFKA_BROKERS}`, `rmu-api-<name>`, `rmu-api-<name>-consumer` (only the APIs that consume events).

|`RMU_API_<OTHER>_URI`
|`http://rmu-api-<other>:<port>/v1`
|===

The IAM, Kafka and `LOG_LEVEL` blocks are YAML anchors (`x-iam-env`, `x-kafka-env`, `x-log-env`) merged into each service that reads them. The naming convention and the legacy names still set for older images are in link:configuration.adoc[]. Service-specific variables:

* *Users* also reads `RMU_IAM_ADMIN_URI` (`${RMU_IAM_BASE_URI}/admin/realms/${RMU_IAM_REALM}`) and `RMU_USERS_ACTIVATION_CODE_SIZE`.
* *Media* reads `RMU_MEDIA_S3_*` and `RMU_MEDIA_IMAGE_*`, passed from the same names in `.env`.
* *NPCs* is not aligned yet: it reads `RMU_IAM_BASE_URL` and `RMU_KAFKA_PARTITION_COUNT`.
* *Attack Tables* (NestJS without Mongo or Kafka since workspace spec 035) reads the IAM and `LOG_LEVEL` blocks, `PORT`, `RMU_THROTTLE_LIMIT` (1000) and `RMU_ATTACK_TABLES_DIR` (`/data/tables`, a read-only bind mount of `RMU_ATTACK_TABLES_DATA_DIR`). Every endpoint but `/v1/health` needs a token, and the whole tables (`GET /v1/<kind>-tables/{id}`) the `rmu-core-law` group. Without a workspace data folder it serves the tables bundled in its image (every Core Law attack, critical and fumble table, no spell casting tables); see link:configuration.adoc#attack-tables-data[Attack tables data].

When adding a service, follow the same pattern and add it to this table, `compose/apis.yaml`, the gateway routes (`compose/config/caddy/Caddyfile`) and the context diagram.
