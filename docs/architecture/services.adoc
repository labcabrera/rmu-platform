= Services catalog
:toc: left

Every service lives in its own repository and publishes its own image. `rmu-platform` consumes the images in `compose/apis.yaml`, with versions pinned through `RMU_API_<NAME>_VERSION` in `.env`.

=== Environment convention

APIs are configured through `RMU_*` variables. In `compose/apis.yaml` they are built from the shared values in `.env`:

[options="header",cols="2,3"]
|===
|Variable |Value

|`RMU_MONGO_<DOMAIN>_URI`
|`${MONGO_BASE_URI}/rmu-<domain>?authSource=admin`

|`RMU_IAM_JWK_URI`, `RMU_IAM_TOKEN_URI`
|`${KEYCLOAK_BASE_URI}/realms/${KEYCLOAK_REALM}/protocol/openid-connect/{certs,token}`

|`RMU_IAM_CLIENT_ID`, `RMU_IAM_CLIENT_SECRET`
|The confidential `rmu-client` (`KEYCLOAK_CLIENT_ID`, `KEYCLOAK_CLIENT_SECRET`).

|`RMU_KAFKA_BROKERS`, `RMU_KAFKA_CLIENT_ID`, `RMU_KAFKA_CONSUMER_GROUP_ID`
|`${KAFKA_BROKERS}`, `rmu-api-<name>`, `rmu-api-<name>-consumer`.

|`RMU_API_<OTHER>_URI`
|`http://rmu-api-<other>:<port>/v1`
|===

The IAM, Kafka and `LOG_LEVEL` blocks are YAML anchors (`x-iam-env`, `x-kafka-env`, `x-log-env`) merged into each service. Exceptions:

* *Users* reads `RMU_IAM_JWKS_URI` (with an S) and `RMU_IAM_ADMIN_BASE_URL`.
* *Attack* (Python) reads `RMU_MONGO_ATTACK_URI`, `RMU_MONGO_ATTACK_DATABASE` and `RMU_API_ATTACK_TABLES_URL`.
* *Media* reads its S3 settings from the `AWS_*` and `MEDIA_ASSETS_URI` values.

When adding a service, follow the same pattern and add it to this table, `compose/apis.yaml`, the gateway routes (`compose/config/caddy/Caddyfile`) and the context diagram.
